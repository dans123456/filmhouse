1. PROJECT OVERVIEW & ARCHITECTURE
================================================================================
Running "bot.js" on a dedicated Linux VPS keeps the application service online
24/7/365 with uninterrupted connectivity:

- Continuous uptime without relying on personal computer hardware.
- Datacenter-grade bandwidth and ultra-low latency for Telegram bot API calls
  and TMDB metadata queries.
- PM2 process manager automatically restarts the bot upon unexpected exits or 
  system reboots.
- Operates in Telegram "Polling Mode" (--polling), eliminating the need for 
  inbound open ports, public domain records, or custom SSL certificate handling.

================================================================================
2. SECURITY & CREDENTIALS SAFETY RULES
================================================================================
- NEVER share your SSH Private Key (.key / .pem) with anyone or upload it 
  to public repositories. It is the master access credential to your server.
- NEVER share your Firebase service account private key (firebase-key.json) 
  publicly. Keep it in your .gitignore.
- Keep all bot tokens and database secrets isolated inside the .env file.
- Use non-root user permissions ("ubuntu") for daily service management.
- Ensure all remote maintenance is performed over encrypted SSH channels.

4. STEP-BY-STEP: CREATING YOUR UBUNTU VM INSTANCE ON ORACLE CLOUD
================================================================================
1. Log in to your Oracle Cloud Console: https://cloud.oracle.com/
2. Navigate to Compute -> Instances -> Create Instance.
3. Name your instance: e.g., "filmhouse-server".
4. Placement: Keep default Availability Domain.
5. Image and Shape:
   - Select Image: Canonical Ubuntu (Ubuntu 22.04 LTS or 24.04 LTS).
   - Select Shape:
     * Option A (Recommended): Ampere ARM (VM.Standard.A1.Flex) - up to 4 OCPUs, 24GB RAM.
     * Option B (Fallback): AMD Micro (VM.Standard.E2.1.Micro) - Always Free 1GB RAM.
6. Networking:
   - Ensure "Assign a public IPv4 address" is enabled.
7. SSH Key Pair Generation:
   - Select "Generate a key pair for me".
   - Click "Save Private Key" and store the file in a secure private folder.
8. Click "Create" and wait for the instance status to turn green ("Running").
9. Note your Public IP Address from the instance details screen.

5. STEP-BY-STEP: CONNECTING TO YOUR UBUNTU SERVER VIA SSH
================================================================================
From your local terminal (PowerShell, Command Prompt, or Linux/macOS shell):

1. The default username for Ubuntu on Oracle Cloud is: "ubuntu".
2. Run the connection command:

   ssh -i "<PATH_TO_YOUR_PRIVATE_KEY>.key" ubuntu@<YOUR_SERVER_PUBLIC_IP>

   Example:
   ssh -i "C:\path\to\your-key.key" ubuntu@129.153.xx.xx

3. When prompted "Are you sure you want to continue connecting (yes/no)?", type "yes".
4. You are now logged into the Ubuntu command line.
5. Type "exit" anytime to disconnect back to your local machine.

6. STEP-BY-STEP: TRANSFERRING BOT FILES FROM YOUR PC TO THE SERVER
================================================================================
From your local machine terminal inside your project directory:

Run the secure copy command (scp) to transfer required application files:

scp -i "<PATH_TO_YOUR_PRIVATE_KEY>.key" bot.js package.json firebase-key.json .env ubuntu@<YOUR_SERVER_PUBLIC_IP>:~/

Transferred items:
- bot.js (application service logic)
- package.json (runtime dependencies list)
- firebase-key.json (Firebase service account credentials)
- .env (local environment configuration variables)

Alternatively, connect via SFTP using FileZilla:
- Protocol: SFTP - SSH File Transfer Protocol
- Host: sftp://<YOUR_SERVER_PUBLIC_IP>
- Logon Type: Key file -> Select your saved private key.
- User: ubuntu
- Port: 22

7. STEP-BY-STEP: INSTALLING DEPENDENCIES AND LAUNCHING 24/7 WITH PM2
================================================================================
Connect to your server via SSH:
ssh -i "<PATH_TO_YOUR_PRIVATE_KEY>.key" ubuntu@<YOUR_SERVER_PUBLIC_IP>

Execute the following commands sequentially:

1. Update system packages:
   sudo apt update && sudo apt upgrade -y

2. Install Node.js LTS (v20.x) & Git:
   curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
   sudo apt install -y nodejs git

   (Verify installation: node -v && npm -v)

3. Install PM2 process manager globally:
   sudo npm install -g pm2

4. Install application dependencies:
   cd ~
   npm install --omit=dev

5. Launch the bot service with PM2 in polling mode:
   pm2 start bot.js --name "filmhouse-bot" -- --polling

6. Configure PM2 auto-restart on system reboot:
   pm2 save
   sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u ubuntu --hp /home/ubuntu

8.1 SAFE 1-CLICK UPDATE SYSTEM (ZERO-DOWNTIME RELOAD)
================================================================================
Whenever updates, enhancements, or catalog data fixes are committed to GitHub, 
the live bot can be safely updated without manual file editing:

METHOD 1: TELEGRAM ADMIN COMMAND (FASTEST)
- Send /update or /upgrade to the bot in private chat.
- The service pulls the latest commit, runs syntax validation ("node -c bot.js"),
  and gracefully reloads PM2 with zero downtime.
- Restricted exclusively to authorized Master Admin accounts.

METHOD 2: ADMIN CONSOLE ONE-CLICK SYNC
- Open the Admin Console -> Settings -> Telegram Bot tab.
- Click "⚡ Pull Latest Code from GitHub".
- Real-time status indicators monitor progress and confirm clean reload.

METHOD 3: SERVER TERMINAL SCRIPT
- If already in an SSH session, run:
  ./update.sh

9. CHANNEL AUTOMATION & MEDIA CATALOG MANAGEMENT
================================================================================
How bot.js manages media metadata and automated catalog operations:

1. Metadata Extraction & TMDB Cataloging:
   When an administrator posts a title entry to the configured channel, 
   the bot extracts the title and year, queries The Movie Database (TMDB) API, 
   and retrieves verified metadata (posters, genres, synopsis, ratings, and crew).

2. Firestore Catalog Synchronization:
   The bot automatically inserts or updates the verified metadata entry in the 
   Firestore "movies" collection, making it instantly browsable in the client app.

3. Automated Notification Dispatch:
   The bot cross-references the "requests" collection. When a requested title 
   is cataloged, the requesting user receives an automated completion notification.

4. Priority Alert Notification:
   When a user submits or boosts a request in the application, the bot 
   dispatches an instant notification to authorized administrators.

10. COMMON GOTCHAS & TROUBLESHOOTING
================================================================================
1. "Out of host capacity" during VM creation:
   - Ampere A1 shapes can occasionally have high demand in specific data centers.
   - Fallback: Select the AMD shape (VM.Standard.E2.1.Micro) which is always 
     available and provides ample resources for the Node.js bot.

2. Windows SSH Key file permission warnings:
   - If Windows OpenSSH flags overly broad key permissions:
     Right-click key file -> Properties -> Security -> Advanced:
     Disable inheritance, remove extraneous users, and grant your account Full Control.

3. Network Mode:
   - Running in polling mode (--polling) avoids all firewall, domain routing, 
     and SSL port binding requirements, making it the most reliable setup on a VPS.
